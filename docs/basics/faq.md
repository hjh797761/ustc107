# 常见问题

本页面按问题类型整理第一次使用平台时常见的疑问。遇到报错时，建议先确认自己在哪个节点、运行了什么命令、作业号是多少、日志里最后几行写了什么。

## 账号与权限

### 我应该在哪里登录平台？

本科生算力平台入口为 [https://107.ustc.edu.cn/dashboard](https://107.ustc.edu.cn/dashboard)。目前主要通过统一身份认证和网页端访问平台。

进入平台后，通常可以通过 Web Shell 使用 Linux 终端，并通过文件管理器上传、下载和编辑文件。

### 个人密码是什么？

群内当前说明中，个人密码目前是随机生成的密码；后续是否支持自行修改，以平台后续方案为准。

如果你无法登录或密码不可用，请优先查看平台页面、课程通知或联系相关维护人员。

### 平台能不能 SSH 登录？

当前群内说明中，平台目前不支持 SSH 登录，主要通过网页端 Web Shell 和文件管理器使用。

如果你之前使用过其他服务器或实验室服务器，请注意它们和本科生算力平台不是同一个入口，账号、密码和访问方式可能不同。

### 能不能申请更多资源？

可以。若课程任务确实需要更长运行时间、更多 CPU、更多 GPU 或多卡任务，可以通过平台提交额外算力申请：

[https://107.ustc.edu.cn/apply](https://107.ustc.edu.cn/apply)

申请前建议先用较小资源跑通测试任务，确认代码、环境和数据路径没有问题。

## 环境与依赖

### 平台有没有统一 conda 环境？

群内当前说明中，平台目前需要用户自己配置环境，不应假设已经有统一可用的 conda 环境。

如果项目依赖较简单，可以先使用 Python 自带的 `venv`：

```bash
python3 -m venv ~/envs/myenv
source ~/envs/myenv/bin/activate
python -m pip install --upgrade pip
```

如果项目依赖较复杂，可以考虑使用 Miniforge、mamba 或 conda，并在作业脚本中写清楚环境初始化和激活命令。

### 为什么每次提交作业都像找不到 conda？

在 Web Shell 中手动激活过环境，不代表 Slurm 作业里会自动激活同一个环境。作业脚本是一个新的运行过程，需要在脚本里写出环境激活步骤。

例如使用 `venv` 时：

```bash
source ~/envs/myenv/bin/activate
which python
python -V
python main.py
```

如果你使用 Miniforge 或 conda，需要先加载对应的初始化脚本，再激活环境。具体路径取决于你的安装位置。

### 为什么 PyTorch 装成了 CPU 版本？

如果在登录节点安装 PyTorch，登录节点不一定能看到 GPU，安装工具可能默认选择 CPU 版本。群内已有同学通过强制指定 CUDA 版本解决，例如：

```bash
CONDA_OVERRIDE_CUDA="12.4" conda install pytorch torchvision torchaudio pytorch-cuda=12.4 -c pytorch -c nvidia -y
```

使用前建议先清理错误安装的环境或重新创建环境，避免 CPU 版本和 GPU 版本混在一起。

### 为什么命令在本地电脑能运行，在平台上不行？

本地电脑和平台是两个不同环境。常见差异包括：

| 差异 | 说明 |
|---|---|
| 文件路径不同 | 本地路径不能直接用于平台 |
| Python 环境不同 | 本地安装过的包，平台上不一定有 |
| 操作系统不同 | 本地 Windows 命令和 Linux 命令可能不同 |
| 硬件资源不同 | GPU、CPU、内存需要通过平台申请 |
| 当前目录不同 | 运行命令前需要确认 `pwd` 和 `ls` |

迁移项目时，建议先做小规模测试，确认文件、环境和命令都能在平台上运行，再提交正式任务。

## 任务调度

### 为什么不要在登录节点直接跑训练？

登录节点主要用于登录平台、整理文件、配置环境和提交任务。长时间训练、推理、渲染、批量数据处理等任务应通过 Slurm 提交到计算节点运行。

如果在登录节点直接运行重计算任务，可能会影响其他同学登录、编辑文件或提交作业。

### 默认应该使用什么分区和 QoS？

群内当前说明中，统一认证登录的同学默认使用 `Students` 分区，QoS 使用 `qos_stu_default`，初始算力配额为 `4CPU / 1GPU / 4h`。

基础示例：

```bash
#SBATCH --partition=Students
#SBATCH --qos=qos_stu_default
#SBATCH --gres=gpu:1
#SBATCH --cpus-per-task=4
```

如果平台页面、课程说明或管理员通知有新的参数要求，请以最新说明为准。

### 为什么我写 `qos_stu_medium` 会报错？

群内当前说明中，统一认证登录的学生默认可用 QoS 是 `qos_stu_default`。如果没有额外权限，写其他 QoS 可能会提交失败。

建议先使用：

```bash
#SBATCH --qos=qos_stu_default
```

如确实需要更高资源，应通过平台申请。

### 为什么任务一直是 `PD`？

`PD` 表示 Pending，也就是任务还在排队。

常见原因包括：

| 可能原因 | 建议检查 |
|---|---|
| 当前资源暂时不够 | 等待一段时间后再查看 `squeue -u $USER` |
| 申请资源过多 | 检查脚本里的 CPU、GPU、运行时间等参数 |
| 分区或 QoS 不合适 | 对照平台页面、课程说明或管理员通知 |
| 自己已有任务占用资源 | 用 `squeue -u $USER` 查看自己的任务 |

查看任务状态：

```bash
squeue -u $USER
```

如果确认任务不需要了，可以取消：

```bash
scancel <作业号>
```

### 为什么出现 `QOSMaxCpuPerUserLimit`？

这个错误通常表示任务违反了当前 QoS 的资源限制，例如 CPU 申请过多，或已有任务占用了当前账号的可用配额。

可以先检查：

```bash
squeue -u $USER
```

并确认脚本里的 CPU 参数没有超过默认限制：

```bash
#SBATCH --cpus-per-task=4
```

如果确实需要更多 CPU 或更长时间，请通过平台申请额外算力。

### 可以指定使用 5090 或 A100 吗？

可以。群内当前说明中，`anode16`、`anode17` 为 A100，其他相关 GPU 节点为 RTX 5090。

申请 1 块 RTX 5090：

```bash
#SBATCH --gres=gpu:5090:1
```

申请 1 块 A100：

```bash
#SBATCH --gres=gpu:A100:1
```

如果没有明确需求，建议先使用默认 GPU 申请方式：

```bash
#SBATCH --gres=gpu:1
```

### 为什么提交任务后没有日志？

先确认 `sbatch` 是否真的提交成功。成功时通常会看到：

```text
Submitted batch job 12345
```

然后检查作业脚本里的日志路径和日志目录是否存在：

```bash
ls ~/logs
```

如果没有日志目录，可以先创建：

```bash
mkdir -p ~/logs
```

排查错误日志：

```bash
tail -n 50 ~/logs/<日志文件名>.err
```

## 存储与数据

### 为什么提示找不到文件或目录？

常见原因是当前目录不对，或者脚本里的路径写错了。

在 Web Shell 中可以先检查：

```bash
pwd
ls
```

在作业脚本中，建议明确进入项目目录：

```bash
cd ~/projects/<你的项目目录>
python main.py
```

如果程序需要数据文件，也要确认数据路径在计算任务中能访问到。不要只凭本地电脑上的路径判断平台上也存在同样文件。

### 上传项目时应该注意什么？

如果项目是一个文件夹，建议先在本地电脑打包，再通过平台文件管理器上传到 `~/projects`。上传后进入平台检查文件是否存在：

```bash
cd ~/projects
ls
```

如果上传的是压缩包，解压后也要再次检查目录结构，确认代码、数据和配置文件都在预期位置。

### 可以把平台 home 目录当网盘长期堆文件吗？

不建议。平台存储主要服务课程作业、训练项目和实验结果。应及时清理无用日志、中间文件和旧 checkpoint，避免影响后续任务和共享存储使用。

## 求助前应该准备什么

向同学、助教或维护者求助前，建议准备：

- 你执行的命令；
- 你提交的作业脚本；
- `sbatch` 返回的作业号；
- `squeue -u $USER` 的输出；
- `.out` 日志；
- `.err` 日志；
- 你希望程序完成什么任务；
- 你已经尝试过哪些解决方法。

这些信息能帮助别人更快判断问题出在账号权限、环境依赖、任务调度、存储数据，还是程序本身。
